Bugs Found & Fixed

BUG 1 — Invalid Gemini model identifiers Critical

File: src/server/gemini.ts line 80–85

Root cause: CANDIDATE_FLASH_MODELS contained 'gemini-3.1-flash-lite', 'gemini-3.8-flash' — neither exists in the Google GenAI API. All 4 retry attempts would fail with "model not found" at runtime.

Fix: Replaced with valid current model IDs: 'gemini-2.5-flash', 'gemini-2.5-flash-lite', 'gemini-flash-latest'.

BUG 2 — ThinkingLevel.MINIMAL does not exist Critical

File: src/server/gemini.ts line 106

Root cause: ThinkingLevel.MINIMAL is not a valid value in @google/genai@2.24.0. Valid values are NONE, LOW, MEDIUM, HIGH, AUTO. Calling the API with this enum would throw a runtime error.

Fix: Replaced ThinkingLevel.MINIMAL → ThinkingLevel.NONE for gemini-2.5-flash-lite; removed invalid ThinkingLevel.LOW block for the non-existent gemini-3.8-flash.

BUG 3 — Duplicate entry in CANDIDATE_FLASH_MODELS wastes a retry slot Medium

File: src/server/gemini.ts line 80–85

Root cause: 'gemini-3.1-flash-lite' appeared at indices 0 and 2. With 4 attempts cycling through 4 slots, 2 of 4 retries used the same (invalid) model.

Fix: Replaced array with 4 distinct valid model identifiers. Index 0 and 3 both use 'gemini-2.5-flash' as a final fallback, which is intentional and different from the lite/alias variants.

BUG 4 — esbuild peer dependency version conflict blocks npm install Medium

File: package.json

Root cause: "esbuild": "^0.25.0" in dependencies conflicts with vite@8.3.x peer requirement esbuild@^0.27.0 || ^0.28.0. npm install fails with ERESOLVE. bun resolves this via nested deduplication but npm users cannot install the project.

Fix: Updated "esbuild": "^0.28.0" in dependencies (esbuild is also used at runtime in verifier.ts via import { transform } from 'esbuild').

BUG 5 — Verifier bad-model detection regex missed new invalid names Medium

File: src/server/verifier.ts lines 654–655 and 1048–1049

Root cause: The static analysis regex only flagged old well-known names like gemini-3.5-flash, gemini-1.5-flash but not the incorrect gemini-3.x-* pattern variants that were actually in the app's own gemini.ts.

Fix: Updated regex to /model\s*:\s*['"\`](gemini-3\.[0-9][^'"\`]*|gemini-1\.[0-9][^'"\`]*|gemini-pro|gemini-2\.0-flash[^'"\`]*|gemini-2\.0-pro)['"\`]/ to catch all invalid 3.x, 1.x, and 2.0 patterns in student-uploaded code. Replacement suggestion updated from gemini-flash-latest → gemini-2.5-flash.

Security Findings

SECURITY-1 — Insufficient testCommand execution blocklist (FIXED) Medium

File: src/server/verifier.ts line ~1127

Finding: The original blocklist only blocked rm -rf /, mkfs, and fork bombs. Commands like curl http://... | sh, wget, chmod +x, /dev/tcp (bash TCP redirection), and others were not blocked. testCommand values come from Gemini-generated content stored in DB, not direct user input — but defense-in-depth is warranted.

Fix: Expanded blocklist to include curl, wget, nc, netcat, /dev/tcp, bash -i, sh -i, writes to system directories, chmod 777/+x, and sensitive file paths.

SECURITY-2 — Authentication & Authorization Pass

  • All project routes require a valid Firebase ID token via requireStrictFirebaseAuth
  • Every project-scoped DB query includes eq(projects.ownerId, userId) ownership check
  • No cross-user data leakage possible via parameterized Drizzle ORM queries

SECURITY-3 — ZIP Path Traversal Pass

Extracted ZIP content is stored as text in PostgreSQL, never written directly to the filesystem from the ZIP. The verifier sandbox uses path.normalize().replace(/^(\.\.[\/\\])+/, '') + path.join(sandboxDir, ...) for any writes.

SECURITY-4 — Secret Handling Pass

All secrets (GEMINI_API_KEY, Firebase Admin credentials, DATABASE_URL) are server-only environment variables. Firebase client config is intentionally injected into the frontend (standard Firebase pattern). No secrets are stored in the database or returned to the frontend.

SECURITY-5 — No CORS Middleware Low / Informational

Finding: server.ts does not configure cors() middleware. All origins can make cross-origin requests to /api/*.

Assessment: Not fixed — all sensitive routes require Authorization: Bearer <Firebase ID token>. A cross-origin attacker cannot obtain a valid token without the user's interaction. Impact is limited to the public endpoints (/api/health, /api/auth/firebase-config) which contain no sensitive data.
